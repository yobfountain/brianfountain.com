AI PRODUCT DESIGN

Where the machine ends and the person begins

Every product I have built on a generative model comes down to the same design question: what should the model do, what should the person do, and what does the interface owe each of them? Five products answer it five ways. One runs an animation studio's production pipeline. Another is a novel outline that never leaves your browser.

G3NPRO
Founder and product design lead2025–now, with customers
g3npro.com

A production platform that turns a script into animation, with people making the calls that matter

The model doesBreaks a script into beats, plans coverage, writes shot prompts, generates images, video, voices, music and effects.
The person doesApproves every shot that ships, edits what the agents drafted, and cuts the timeline.
The interface owes themReview that is faster than generation, so human judgment is the quickest step in the system rather than the bottleneck.

G3NPRO is a platform for mid-tier and enterprise animation studios, with studio customers. The domain model mirrors real production: a property holds projects, a project holds a script parsed into scenes, and each scene breaks into shots. The centerpiece is the Director Agent, a Claude-powered cinematography system that reads a scene, plans the coverage, chooses shot types and angles, and writes visual prompts in cinematic language. It works autonomously to produce a full shot list, or interactively, refining shots in response to a person's notes.

The product design decisions that matter most are about the agent's shape. Every exchange with the model runs through structured schemas, so its output lands in the database as scenes and shots instead of prose someone has to transcribe. The in-app agent operates the platform through a small set of typed tools, so its actions go down the same code paths as a person's. When a script mentions a new character, an enrichment agent drafts a description and references that a person can accept, edit or throw away. Background jobs only ever write to the database; the interface listens and redraws itself, which keeps it honest about what is actually on file.

Underneath, the generation pipeline is built to outlive its providers. Every request is classified by purpose: a character portrait, a lip-synced shot, a music score, forty-five purposes in all, and a purpose says nothing about which model produces it. A factory maps each request to one of more than a dozen provider adapters, including Runware, Kling, Runway, fal.ai, BytePlus, ElevenLabs, Tripo3D and self-hosted ComfyUI on Modal. Before anything generates, a strategy resolver looks at what the subject already has and cascades to the best technique: a trained LoRA for identity if the character has one, reference conditioning if there are references, plain text-to-generation as the floor. The assets on file enforce consistency, so prompt wording can stay loose. Characters get their own LoRAs, trained on image sets captioned inside the platform through a Python training API I built on GPU infrastructure.

GenBuzz
Founder, editor2025–now
genbuzz.news

A publication where agents draft and a person decides what runs

The model doesIngests sources continuously, extracts the entities, and drafts each story with attribution.
The person doesApproves, edits or drops every draft before it publishes.
The interface owes themA desk where approving is the whole job, so the human pass stays short enough to happen every day.

GenBuzz covers AI filmmaking and generative production: tools, funding, acquisitions, legal, research and events. It is an agentically managed publication. An automated pipeline ingests third-party reporting and announcements, extracts entities, and drafts stories that link and credit their sources. Nothing publishes until I approve it. The design bet is that the editorial gate is the product: the agents make the volume possible, and the human pass is what makes it worth reading.

Readers get the same principle from the other side. The newsletter is customizable by category, so a person who cares about legal decisions and not about funding rounds gets a different issue from the one who wants the tools. GenBuzz also does a second job for me: covering this field daily is my frontier radar, surfacing new models and workflow patterns before they reach my other products.

Vibeside
Founder2025–now, early access
vibesi.de

A command center for side projects, where you review the running app instead of the diff

The model doesTakes a task on whichever project has your attention, works in an isolated branch, and reports what it changed.
The person doesDispatches in a sentence, looks at the live preview, replies, and ships when it looks right.
The interface owes themEverything from a phone, in the gaps in a day, with a push when a task needs a decision.

Vibeside is a bet on what product development looks like when it happens on a phone. It's a lightweight mobile IDE built around one loop: ask for a revision, then review the running result. When you like what you see, tap publish.

Under the hood, Vibeside is a self-hostable panel for all the side projects you keep half finished. You hand a task to Claude Code on any project, on any machine you own, and come back to review the running app rather than the code. Each task gets its own git worktree, so work is isolated and previewable. The live preview is a first-class toggle inside the task, and the routes the agent touched are surfaced as deep links, so reviewing a login flow means tapping through the login flow.

The core design idea is that a task is a conversation: you reply, the agent works again, and the task stays open until you merge it. A task moves from queued to running to needs review to merged, and running and needs review alternate as you reply. Needs review and failed send a web push, so progress does not depend on you being at a desk. Architecturally, the panel is a control plane and the agent is a data plane: Claude Code, your source, and your git and deploy keys never leave the machines you own. The panel only sends commands and shows what came back, which is what makes it safe to drive from a browser on a train.

1K Notes
Founder2025–now
1knotes.com

A picture is worth a thousand notes

The model doesReads a photograph and writes an original song from it, melody and lyric included.
The person doesChooses the picture, which is the entire creative act asked of them.
The interface owes themOne step, no vocabulary, and a way to hear what everyone else made.

1K Notes is a creative tool for people who would never describe themselves as songwriters. You attach a photo and the model turns it into a prompt for a song, then into the song itself. The interface asks for one thing, a photo, on purpose: the photo carries the mood and the specifics, and asking a non-musician to add anything else would only get in the way. This is the product where I learned most about teaching non-technical people to work with a generative system, because the lesson had to fit in a single tap.

All images are public, and every song lands in a gallery and a radio stream, so the output of one person's afternoon becomes the thing that shows the next person what the tool can do.

Chapters
Creator2025
chapters.brianfountain.com

A novel outline that never has to leave your computer

The model doesSuggests the next story beat from the ones you have written, across twenty-seven beats and three acts.
The person doesWrites, accepts, rewrites, and locks the beats they want kept.
The interface owes themPrivacy by default, and an honest account of the trade when they opt into more power.

Chapters takes a one-line premise and helps a writer build it into a complete outline using the twenty-seven-chapter structure: nine beats each for setup, confrontation and resolution. Each beat is a field the writer can fill in, generate, or lock so that later generations leave it alone. Progress reads as beats written out of twenty-seven, and the finished outline downloads as a file the writer owns.

The design decision I care about most is the model switch. By default Chapters downloads a small language model into the browser and runs it there, so a first draft of someone's novel never leaves their machine, at the cost of a slight pause while it thinks. A toggle switches to Claude for higher-quality suggestions, and the interface says plainly what that costs: the text goes to Anthropic's servers, and the requests draw on a daily limit shared by everyone using the tool, which can run out. Writers get to choose between private and better, with the terms stated at the point of choice rather than in a policy page.

What the five have in common

These are working systems I operate, and the design rules come out of running them every day. Agents fail at taste, at noticing an ambiguous spec, and at verifying their own output, so the products put people at exactly those points and make everything else fast.

The first rule is a gate at the point of consequence: shot review in G3NPRO, editorial approval in GenBuzz, the needs-review state in Vibeside, the lock on a beat in Chapters. Nothing with a consequence ships without a person seeing it. The second is that agents use the same doors as people. Typed tools and structured schemas mean an agent's action goes down the code path a human's would, and its output arrives as data rather than prose. Third, purpose over provider. Models change monthly, so classify what the product needs and keep the model choice behind an adapter. A better model becomes a swap rather than a rewrite.

Then the interface. A system that generates hundreds of assets is only as good as the speed at which a person can judge them, so the review screen gets more design attention than anything else I build. And the trade is stated where the choice is made: local by default in Chapters, and keys that never leave your machines in Vibeside.

The last rule connects this page to the other half of my work. I author Claude Code skills that encode my own production standards, so agents apply them without supervision. It is the same idea as writing a teacher-training process. Put the standard down where the next worker will find it.

The instructional design behind all of this, from bootcamp classrooms to a global sales organization, is collected at brianfountain.com/work/instructional-design. Teaching non-technical people to work with AI systems is the main thing these products have to do, and it turns out to be the same job.
